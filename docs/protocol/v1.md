# SourceTrace Edge Protocol v1

Status: portfolio prototype specification, 2026-07-30.

## Scope

The protocol carries small controller messages over a reliable or unreliable
byte stream. It defines framing, corruption detection, command authentication,
replay decisions, retry behavior, and compatibility. It does not provide
confidentiality, device enrollment, key rotation, or exactly-once transport.

## Envelope

All integers are unsigned and encoded in network byte order.

| Offset after length | Field | Size | V1 rule |
|---:|---|---:|---|
| –4 | Body length | 4 | 48–4208; validated before buffering the body |
| 0 | Magic | 2 | ASCII `ST` |
| 2 | Version | 1 | `0x01` |
| 3 | Header length | 1 | `0x2c` (44) |
| 4 | Message type | 1 | Enum below |
| 5 | Flags | 1 | Bits 0–1 only |
| 6 | Error code | 2 | Zero unless error flag/type |
| 8 | Device identifier | 16 | Opaque UUID bytes |
| 24 | Sequence | 8 | Monotonic per authenticated sender/device |
| 32 | Monotonic milliseconds | 8 | Diagnostic ordering, not an expiry proof |
| 40 | Payload length | 4 | 0–4096 and must match outer length |
| 44 | JSON payload | variable | UTF-8 object with message schema |
| variable | Ed25519 signature | 0 or 64 | Present exactly when authenticated flag is set |
| final 4 | CRC32 | 4 | IEEE CRC32 over magic through signature |

Maximum frame size including the four-byte prefix is 4212 bytes.

### Message types

1. registration
2. configuration
3. command
4. telemetry
5. acknowledgement
6. error

Unknown v1 values are rejected. V1 flags are `0x01` authenticated and `0x02`
error; all other bits are reserved and rejected. Error frames require both type
6 and the error flag. Non-error frames require error code zero.

## Payload bounds

The parser first validates both lengths and CRC, then authenticates protected
messages, then parses JSON. JSON is limited to depth 8, 32 object members, 64
array elements, 64-byte keys, and 256-byte string values. Message-specific
schemas reject unknown fields.

Configuration interval is 250–60,000 ms. Command and event identifiers are
limited to 64 bytes. This bounded JSON is an encoding choice for the prototype;
the outer frame remains binary and stream-safe.

## Authentication

Configuration and command messages require an Ed25519 detached signature. The
signature input is:

```text
"SourceTraceEdge/v1\0" || fixed-header || raw-payload
```

The authenticated flag is already present in the signed header. The signature
does not cover the outer length or CRC; their values are nevertheless
cross-checked against the signed header and received body.

Validation order is: bounds, header, duplicated lengths, CRC32, Ed25519,
replay decision, JSON, schema, application authorization. CRC32 is only an
accidental-corruption check. It is not authentication.

## Replay and idempotency

Replay state is indexed by authenticated sender/device:

- sequence above the durable high-water mark: candidate new message;
- same sequence and same signature: duplicate acknowledgement, no repeated
  application effect;
- same sequence and different signature: `sequence_conflict`;
- lower sequence: `replay_rejected`.

The parser does not advance the high-water mark. The runtime commits the
accepted sequence, signature, command effect, audit record, and resulting
checkpoint in one persistence transaction.

Outbound telemetry carries an `eventId`. Receivers deduplicate that identifier.
A crash after remote receipt but before local acknowledgement can retransmit a
frame. The protocol therefore claims idempotent effects, not exactly-once
transport.

## Retry semantics

The sender retransmits the identical frame at 250 ms, 500 ms, 1 s, 2 s, and
4 s. After five failed attempts the event remains in the persistent queue until
a later connectivity transition. No unbounded in-memory retry loop is allowed.

## Compatibility

V1 requires header length 44 and rejects unknown flags, enums, and versions.
A future version must use a new version number. A future reader must never
reinterpret a rejected v1 field using guessed semantics.

## Explicit protocol errors

The wire error enum covers invalid length, magic, version, header, message type,
flags, error code, payload length, CRC, authentication, signature, JSON, schema,
replay, sequence conflict, and internal failure. A parser error is fatal to the
current frame; a transport may close and reconnect rather than attempt byte
resynchronization.

## Malformed examples

- `00002000`: body length 8192; rejected after the four-byte prefix.
- Valid frame with payload length `ffffffff`: rejected before payload allocation.
- Valid payload with a changed byte and old CRC: `crc_mismatch`.
- Changed signature with recomputed CRC: `signature_invalid`.
- Authenticated command sequence below the stored high-water mark:
  `replay_rejected`.

The normative golden vector is stored in
`docs/protocol/golden-vectors.json` and asserted by C++ and TypeScript tests.
